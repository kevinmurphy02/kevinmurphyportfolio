CPI Data Pipeline

Turning raw Bureau of Labor Statistics CPI files into a small, validated relational model for inflation analysis.

Format
SQL data pipeline
Context
Personal project
Tools
SQL, MySQL, BLS, Data modeling

The starting data

The Bureau of Labor Statistics publishes monthly Consumer Price Index data in text files. They're useful real-world data, but not immediately ready for the kinds of questions you'd want to ask in SQL.

I used the BLS CPI cu time-series files as raw input and worked through loading, cleaning and modeling them in MySQL.

Turning files into tables

The pipeline normalizes period codes, converts text fields into usable types, filters valid monthly observations and separates the data into a fact table and related dimensions.

01Raw BLS filesText source data
02ValidationTypes and periods
03Relational modelFacts + dimensions
04SQL viewsInflation reporting

Tables include fact_cpi_monthly and dimensions for series, area, item and period. Building that structure means downstream queries don't have to repeat the cleaning logic.

The analysis layer

Once the data is organized, SQL views and window functions can compare the CPI index for a month with the corresponding month in the prior year. One example is the US all-items CPI series, CUUR0000SA0.

I also exported cleaned tables as CSVs for analysis outside MySQL. The focus wasn't a polished dashboard; it was making the input data reliable and the transformation repeatable.

Why I include it

This is a more straightforward project than the machine learning work, but it represents something important: most useful analysis starts with knowing where the data came from and getting it into a structure you trust.
