Good Driver Incentive Program

A full-stack rewards platform connecting drivers, sponsor organizations and administrators.

Format
Web application
Context
Clemson University capstone / Team #06
Tools
Python, Django, MySQL, AWS Elastic Beanstalk, Amazon RDS, GitHub Actions

The idea

Good Driver Incentive Program is a group capstone project at Clemson University. It is designed to encourage safer driving through a points-and-rewards system. Sponsor organizations can award or deduct points based on a driver’s performance, and drivers can use the points they earn to purchase products from that sponsor’s catalog.

The challenge was building more than a single dashboard. The application needs to support three kinds of users, each with different permissions and business tasks.

Three sides of the application

Drivers can apply to sponsors, see their balances, browse rewards, save favorites, check out and view their order history. Sponsors manage their own drivers, review applications, adjust points with reasons, and curate their own product catalogs. Administrators oversee users, sponsor organizations and reporting across the program.

Reward product information can be imported using the Fake Store API. The application also includes notifications for changes such as point activity and orders.

The data problem

A driver can be associated with more than one sponsor, but those point balances cannot be combined. Points earned with one organization should only purchase products in that organization’s catalog.

The data model therefore keeps sponsor memberships and balances separate. Point changes are recorded in a ledger, and checkout relies on database transactions and row locking to check available points and keep purchases and balance updates consistent.

For example, joining two sponsors gives the driver two separate reward accounts, not a single wallet. The diagram above illustrates that principle, not actual customer data.

Imports and reporting

The program includes import tools for sponsor and administrator workflows. Pipe-delimited text files can be validated row by row, with errors reported and invalid rows skipped while valid rows continue processing. Sponsor uploads are constrained to their own organizations.

Reporting supports date filters and CSV downloads for point history, reward purchases, invoices and audit activity. These features matter because business users need to review what happened, not just see the current balance.

Hosting and delivery

The application is built with Django and server-rendered HTML/CSS. It uses MySQL on Amazon RDS and is hosted through AWS Elastic Beanstalk with Gunicorn. GitHub Actions runs tests against MySQL before main-branch deployments.

This was a team-built system. The description here covers the project as a whole rather than claiming that I individually implemented every feature.

The public site has an information page and login. Access to some dashboards requires an account. The repository is intentionally not linked because of the course’s academic privacy requirements.
